Public-contract developer lab

Watch failed additions leave no incomplete fieldset behind

Two controlled failures expose only public result reasons, public lifecycle events, and author-visible DOM. Neither lab reads a registry, calls a private method, or serializes form values.

Scenario and user goal

An integration author needs confidence that a bad template or a failing addon cannot leak a half-configured form group. The goal is to compare item counts and success events before and after each attempt.

Try it

  • Attempt the malformed-template addition and confirm the result is invalid-template.
  • Confirm its item count remains one and its item-added count remains zero.
  • Attempt addon setup with intentional failure enabled and confirm the result is addon-error.
  • Disable intentional failure, retry, and confirm one complete item plus one success event appears.

Accessibility notes

  • Both baseline forms remain semantic and editable before JavaScript initializes.
  • The diagnostic buttons retain focus because the public API Add calls do not request focus.
  • Each lab uses one dedicated polite result region while core structural announcements are disabled for that root.
  • Failure is communicated with text and counts, not color or animation.
  • The page does not predict screen-reader speech; test status timing in target environments.

Developer notes

  • The script imports only EVENTS and createRepeatableFieldset from the copied public ESM asset.
  • Operation results expose only ok, reason, and success snapshots; the demo never renders error objects.
  • Lifecycle listeners subscribe through the frozen exported event constants.
  • The audit-marker addon creates DOM through ownerDocument and returns idempotent cleanup.
  • The intentionally failing addon mutates nothing before throwing.

Lab limits

This page demonstrates deterministic synchronous failures only. It does not expose private rollback registries, simulate asynchronous hooks, validate third-party cleanup, or prove assistive-technology interoperability.
