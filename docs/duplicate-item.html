Opt-in addon demo

Duplicate an item without cloning its fieldset

The Duplicate Item addon asks core to create a fresh-key item from the trusted template. Only deliberately marked supported current state is copied, while the candidate is still disconnected and before any new-item addon setup.

Privacy boundary: this example marks only Name, preferred contact, updates, and Notes. The hidden server ID, password, and file input remain unmarked and are never copied. Payment and credential autocomplete fields are rejected even if marked.

Executable contact example

Edit the saved contact, then choose Duplicate contact. The new fieldset is inserted immediately after its source, receives a fresh stable key, preserves template defaults, and receives focus through the normal Add decision order.

What the copier means

  • Text inputs and textareas copy their current value, not their default.
  • Checkboxes and radios copy checked state; transient indeterminate state does not copy.
  • Single and multiple selects match enabled option values against the trusted template.
  • Disabled, readonly, hidden, file, credential, payment, and custom controls cannot opt in.
  • Server errors, ARIA invalid/error state, custom validity, dirty/touched flags, and validator registrations are rebuilt rather than copied.
