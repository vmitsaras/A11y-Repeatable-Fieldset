Server-rendered edit-form demo

Edit saved contacts without replacing server state

Two saved contacts arrive with persistent record identifiers, stable field names, values, descriptions, and one server validation message. Initialization discovers those fieldsets in place.

Scenario

An account owner returns to correct an emergency-contact form. The component may add or remove groups, but it must not clear saved data, rename existing controls, remove the server error, or report the saved contacts as newly added.

Try it

  • Confirm Ada and Grace keep their saved values and record identifiers after the page initializes.
  • Correct Grace’s telephone number; the plugin leaves the server message author-owned.
  • Add Contact 3 and compare its generated item-N name with the saved contact-1042 and contact-2088 names.
  • Submit with Preview submitted values and inspect the stable names in the URL query string.

Accessibility notes

  • Saved fieldsets, legends, labels, descriptions, and the server error exist before JavaScript runs.
  • The invalid telephone uses both visible error text and aria-invalid; the plugin does not validate or clear it.
  • Initialization emits one init observation and no item-added observation for saved items.
  • Generated contacts receive unique labels, IDs, descriptions, and names without rewriting saved controls.
  • Screen-reader phrasing and browser autofill behavior still require environment-specific manual evidence.

Developer notes

The page listens with the exported EVENTS constants before calling createRepeatableFieldset. The summary stores only event counts. Saved names remain backend-controlled; only the inert template contains __A11Y_REPEATABLE_KEY__.
