Item labels and status messages

Authors own visible Add, Remove, field-label, and legend text. Core owns structural status messages; the opt-in Accessible Reorder addon separately owns its configurable visible Move-button labels.

Item label

The default label is Item. Set a domain-appropriate value through itemLabel or data-item-label, such as Contact, Address, or Participant profile.

The label appears in status messages; it does not rewrite author legends or button labels.

Partial override

createRepeatableFieldset(root, {
  itemLabel: "Address",
  messageFormatters: {
    added: ({ position, count }) =>
      `Address ${position} is ready. ${count} addresses total.`
  }
});

Each callback receives a fresh frozen object containing structural metadata only. No input values, validation content, passwords, file objects, or server errors are exposed.

Fallback and announcement behavior

  • Thrown, non-string, empty, or whitespace-only formatter output falls back for that concept to the English default.
  • A formatter failure cannot roll back a completed Add, Remove, Duplicate, Restore, or Move operation.
  • When an operation reaches a boundary, the item and boundary concepts are combined into one polite status update.
  • Routine structural changes never use an assertive alert.
  • The package does not include locale packs or pluralization libraries; core never generates Add/Remove labels, while Accessible Reorder accepts explicit Move-button label options.
