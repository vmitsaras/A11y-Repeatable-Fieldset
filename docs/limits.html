Configuration and boundary demo

Keep between one and three delivery contacts

The allowed range is explained before the controls. Native disabled buttons and concise status text expose the current boundary without relying on color.

Scenario

A delivery team requires one primary contact and permits at most three contacts. Users can add optional backups and remove them again, but cannot leave the list empty.

Try it

  • Notice that the only Remove button starts disabled because one contact is required.
  • Add two contacts. Focus moves to each new Name field and the third addition reaches the maximum.
  • Confirm Add another delivery contact becomes natively disabled at three.
  • Remove contacts until one remains; focus avoids a Remove button that becomes disabled at the minimum.
  • Choose Preview delivery contacts to review the current names and telephone numbers without leaving the page.

Accessibility notes

  • The visible range instruction is associated with both the component and Add button.
  • Unavailable native buttons use disabled; the plugin does not add redundant aria-disabled.
  • Successful boundary operations produce one combined polite status message rather than separate competing updates.
  • The preview uses the native output element and inserts form values as text, never as HTML.
  • Source order remains keyboard order, and no structural animation is used.
  • Announcement timing, 400% reflow, and forced-colors presentation still need manual browser verification.

Developer notes

This demo configures data-min-items="1", data-max-items="3", and data-item-label="Delivery contact". The component derives command availability and native button state from the same normalized limits. With JavaScript available, the form’s submit handler updates the preview in place; without JavaScript, the form retains its normal GET submission.
