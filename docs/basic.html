Basic progressive-enhancement demo

Add another contact without replacing the form

Start with one conventional contact fieldset. JavaScript reveals the native Add and Remove controls only after it has validated the author markup.

Scenario

A registration form needs one or more emergency contacts. The user can submit the initial contact without JavaScript; with JavaScript they can add or remove complete contact groups while preserving stable field names.

Try it

  • Use Tab to reach Add another contact, then press Enter or Space.
  • Confirm focus moves to the Name field in the new Contact 2 group.
  • Remove Contact 2 and confirm focus returns to Add another contact.
  • Turn JavaScript off and confirm Contact 1 still has a label, a stable name, and normal form submission.

Accessibility notes

  • Every contact is a native fieldset with a meaningful legend; every input has a visible label.
  • Add and Remove are real button type="button" controls in natural DOM order.
  • A user-triggered Add moves focus to the marked Name input. Removal resolves focus before it detaches an active group.
  • One empty author-owned polite status region reports completed changes; it is not an alert.
  • This demo has no structural animation. Browser/assistive-technology announcement timing still requires manual verification.

Developer notes

The module imports only the copied ESM asset and explicitly calls createRepeatableFieldset for this root. The data attributes form the behavior contract; the BEM classes are optional presentation hooks. The template contains the literal __A11Y_REPEATABLE_KEY__ in stable IDs and names, while the existing server key remains server-ada.
