Deterministic failure and recovery demo

Leave the author form usable when initialization fails

This root deliberately starts with a maximum below its minimum. The public initializer rejects the options before revealing controls or changing server-rendered form data.

Scenario

A configuration typo sets data-min-items="1" and data-max-items="0". The page catches the typed public error, shows a safe diagnosis, and offers a deterministic correction and retry.

Try it

  • Before repairing, edit the saved email and confirm the normal submit button remains available.
  • Confirm Add and Remove are still hidden and no lifecycle success event was dispatched.
  • Choose Correct maximum and retry; the script changes only the invalid option and calls the same public initializer again.
  • After recovery, add one subscriber and inspect the now-working enhancement.

What the demo checks

  • The initializer reports the exported invalid-options code.
  • The existing input node, name, and value survive the failed attempt.
  • Enhancement controls retain their authored hidden state.
  • No init, item-added, item-removed, item-moved, or destroy event fires for the failure.
  • A corrected retry creates a clean active instance and dispatches its own single init.

Other known boundaries

  • Native form reset changes values of controls currently in the DOM but does not restore collection structure.
  • File-input values are never assigned, copied, or restored.
  • Untokenized external ID references remain author-owned.
  • Nested repeaters are excluded from the MVP.
  • Autofill, focus scrolling, and assistive-technology speech need real-browser evidence.

Developer notes

The recovery code imports only RepeatableFieldsetError, EVENTS, and createRepeatableFieldset. It changes one known dataset value, never replaces serialized HTML, and does not expose private diagnostics.
